# Preview for Neovim

The library server is the single Node.js and Hono service for saved-note browsing and the
Neovim previews. It serves the library UI, the compact `/?path=...` document
viewer, and the existing interactive Markdown and Typst preview pages. Node.js
reads saved files and watches the active Neovim buffer's file after `:write`.

## Saved notes library

`library/` contains the saved notes browser and compact document
viewer. The unified service entry point is `server-node.mjs`. To
start it yourself from the repository root:

```sh
npm ci
npm run build
npm run serve -- E:/til
```

When running Node directly, use `node server-node.mjs E:/til`. The service also
accepts `node server-node.mjs -- E:/til`.

The service prints its loopback URL as a JSON `ready` event. The library opens
at `/`; a document can be opened in the compact viewer with
`/?path=relative/path.md`, or in the library UI at
`/notes/relative/path.md`. Neovim starts this same service with its
current working directory as the fixed root. A later working-directory change
is rejected with an HTTP conflict instead of changing the service root.

## Local setup

Requires Neovim and Node.js. npm installs dependencies and builds the browser assets;
and runs the preview service. In this repository:

```sh
npm ci
npm run build
```

Add the local directory to `init.lua` (adjust the path if needed):

```lua
vim.opt.rtp:prepend("E:/markdown-preview.nvim")
```

Restart Neovim. All four frontend pages build together into `dist`.
The library UI is under `dist/library`; generated assets are
ignored by Git. Rebuild after editing frontend sources. Run `npm install` again after
changing `package.json` or `package-lock.json`.

Create a distributable ZIP from the compiled frontend assets and runtime files:

```sh
npm ci
npm run package:zip
```

The script builds both Vite frontends and writes
`release/markdown-preview-nvim.zip` at the repository root. The ZIP includes the
installed production dependencies and WASM assets, so no npm install is needed
after extraction. Node.js is required on the target machine; start the service
from the extracted folder with `node server-node.mjs E:/notes`.

Use the plugin commands:

- `:MarkdownPreview` / `:MarkdownStop`
- `:TypstPreview` / `:TypstStop`

Markdown accepts named `.md` buffers and refreshes after `:write`. Cursor scroll
synchronization is always enabled. Relative images stay within the current
Neovim working directory. Node.js renders Markdown, syntax highlighting, and math;
the browser sanitizes and patches the resulting HTML. The preview follows the
system light or dark theme.
The collapsible outline follows Markdown headings (`#` through `######`);
headings written as raw HTML remain visible but do not enter the outline.

Typst requires a saved, unmodified `.typ` buffer to start. Saving recompiles it;
package imports and referenced files resolve from the document directory and
Typst package cache. If a `@preview` package is missing, the Node.js service
downloads its archive from the official package repository, extracts it into
that cache, and retries compilation. This does not require the native `typst`
CLI; first use needs access to the official package repository.
`@local` packages must already be installed. The running Node.js service prewarms the Typst and PDFium
WASM engines after startup. Typst fonts and compilation, and PDF document opening,
wait until the first request. `:TypstPreview` compiles the current document when
requested; Neovim does not manage the service lifecycle. Set `WASM_PREWARM=0`
before starting Node.js to disable both engine prewarms. The older
`TYPST_WASM_PREWARM=0` setting remains supported.
On Windows, installed New Computer Modern Math files
are loaded from the user or system font directory when present. Compiler errors
and warnings are written to the service console. Errors also appear in Neovim
diagnostics and the preview, and can be added to a location list with
`vim.diagnostic.setloclist()`.
The Node.js preview parses Typst source with a Tree-sitter grammar to identify
source headings and block boundaries, including paragraphs, equations, tables,
and multiline code. It inserts position markers at suitable top-level blank
lines and queries their page coordinates during compilation. Cursor movement
and page clicks interpolate between these markers. Pages without markers can
still use text matching after their SVG has loaded. Documents without block
separators have fewer precise navigation points. The preview outline includes
headings written in the source; headings generated by code are omitted. The
library's Typst document view uses the same WASM compiler and renders page SVGs
inline. Editor synchronization remains on the interactive Typst preview page.

Start the preview service yourself before using the Neovim commands. It listens
on `127.0.0.1:49191` by default, and uses the supplied directory as its file
root. Neovim only connects to the running service; it does not start or stop
Node.js. Inactive library documents release generated Typst pages after five
minutes and Typst/PDF document resources after fifteen minutes. Open library
viewers keep their documents active. The WASM engines remain loaded until the
Node.js process exits.

```sh
npm run build
npm run serve -- E:/notes
```

The service root must match Neovim's current working directory. Configure a
different loopback URL in `init.lua` only if you changed `NODE_PREVIEW_PORT`:

```lua
require("node_preview").setup({ server_url = "http://127.0.0.1:49191" })
```

Use `:MarkdownPreview` / `:TypstPreview` to connect. The corresponding `*Stop`
command closes that preview. Deleting or wiping its source buffer, or exiting
Neovim, also closes the single-page preview while leaving the Node.js service
running.

Set `TYPST_WASM_MEMORY=1` in Neovim's environment to receive WASM memory
measurements. Set `TYPST_WASM_FONTS` to a semicolon-separated list of font files
to override the default Windows font candidates. On other platforms, configure
font files explicitly. `TYPST_WASM_PROFILE=1` reports startup, library compile,
and page SVG times. The WASM renderer only sees fonts loaded into its resolver;
fonts embedded in the native `typst` command are separate. Large local fonts
are read on the first Typst request to register their metadata, then read again
when selected.
The default candidates exclude Noto Sans SC and Noto Serif SC; Source Han Sans
and Source Han Serif remain available for Chinese text.

## Layout

- `plugin/preview.lua`: Neovim command entry point.
- `lua/node_preview.lua`: Neovim lifecycle and HTTP control client.
- `server-node.mjs`: unified Node.js and Hono service entry point, HTTP routes, editor control bridge, and render state.
- `library/routes.mjs`: library HTTP routes and document API.
- `library/`: library and compact document viewer frontends.
- `src/markdown` and `src/typst`: Vite-managed pages.
- `src/shared/preview-client.js`: browser-side SSE
  client shared by both pages.
- `package.json`: runtime and build dependencies.

Build all frontends with `npm run build` from the repository root. The
service listens on `127.0.0.1:49191` by default and uses the supplied startup
directory as its root. Set `NODE_PREVIEW_PORT` before starting it to choose a
different fixed port; point Neovim's `server_url` at the same port.
