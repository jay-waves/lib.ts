# Saved notes library

本地 Markdown、Typst、PDF、HTML 和源码浏览器。通过侧栏管理多个目录，保存书签和阅读位置，文件保存后自动更新预览。

## 启动

从源码运行需要 Rust/Cargo、Node.js 和 npm：

```sh
npm ci
npm run build
npm run serve -- /path/to/notes
```

Windows 路径可用 `E:/notes`。打开 <http://127.0.0.1:49191/>；实际地址以启动日志为准。不传目录时恢复已注册仓库，首次使用可在 Repos 中添加目录。

使用说明见 [web/README.md](web/README.md)。

## 配置

| 环境变量 | 用途 |
| --- | --- |
| `PREVIEW_PORT`（兼容 `NODE_PREVIEW_PORT`） | 端口，默认 `49191` |
| `PREVIEW_BIND_ADDRESS` | 监听地址，默认 `127.0.0.1` |
| `PREVIEW_PUBLIC_URL` | 对外访问地址；局域网或反向代理访问时设置 |
| `LIBRARY_DATA_DIRECTORY` | 数据目录，默认 `data/` |
| `TYPST_FONTS` | 自定义 Typst 字体目录或文件路径列表，使用系统路径分隔符 |
| `RUST_LOG` | 日志级别，默认 `info` |

仓库注册、书签和文件访问历史保存在数据目录，笔记留在原目录；阅读位置仅保存在当前浏览器。升级时保留数据目录，迁移后确保仓库路径仍有效。同一数据目录只运行一个服务进程。

字体和许可证随应用分发，无需字体 CDN。Typst 包可能需要首次联网下载；本地包需自行安装。

## 局域网与反向代理

本机默认允许 `localhost`、其子域（例如 `lib.localhost`）、回环 IP 和本机主机名；请求的 Origin 仍需与 Host 的主机名、端口及配置的协议一致。

将监听地址设为 `0.0.0.0`，并设置 `PREVIEW_PUBLIC_URL`。在数据目录的 `access.json` 中加入访问使用的主机名或 IP，修改后重启：

```json
{ "allowedHosts": ["192.168.0.163", "notes.lan"] }
```

条目不含协议、端口或路径。HTTPS 反向代理需设置 HTTPS 公共地址，并保留原始 Host。应用没有用户登录认证，仓库内容只应向可信网络开放。

## 从外部程序打开文件

文件必须位于已注册仓库中：

```sh
curl -X POST http://127.0.0.1:49191/api/library/open \
  -H 'Content-Type: application/json' \
  -H 'Origin: http://127.0.0.1:49191' \
  -d '{"file":"E:/notes/docs/guide.md","line":20,"view":"raw"}'
```

`line` 和 `view` 可省略。服务优先复用已有页面，否则在服务所在机器打开浏览器。使用其他访问地址时，相应调整请求 URL 和 Origin。

## 图片与视频画廊

视频详情页使用按需加载的 Video.js 控件，进入 Gallery 时提前加载控件 JS 和 CSS；首次加载期间只显示封面占位，避免原生控制栏闪现。点击画面播放或暂停；快捷键只在播放器内生效，参考 [mpv 常用键位](https://mpv.io/manual/stable/#keyboard-control)：

| 按键 | 操作 |
| --- | --- |
| 空格 / P（兼容 K） | 播放、暂停 |
| ← / → | 后退、前进 5 秒 |
| ↓ / ↑ | 后退、前进 1 分钟 |
| Shift + ← / → | 后退、前进 1 秒 |
| Shift + ↓ / ↑ | 后退、前进 5 秒 |
| 9 / 0 | 音量减、加 2% |
| M / F | 静音、全屏 |
| [ / ] | 速度除以、乘以 1.1（范围 0.25×～4×） |
| Backspace | 恢复 1× |

倍速菜单与键盘共享速率策略；键盘调出的自定义倍速也会显示为菜单选中项。输入控件、菜单及组合键的优先级由 Video.js 统一管理。

文件树采用浅层、按需加载：启动时只读取仓库根目录，展开或进入目录才读取下一层，直接打开深层文件时只补齐其祖先路径。后端按仓库共享已加载目录的内存列表和原生文件监听；普通文件事件仅使所属目录列表失效，忽略规则变化重新校验已加载目录。未打开的子目录不递归扫描，不保存目录展开状态，也不新增磁盘或浏览器持久化文件树快照。文件树和目录列表每批挂载 256 项，滚动到末尾自动继续加载。正文、文件路径搜索独立遍历搜索范围，不依赖当前浏览树；Files 范围输入查询后才执行搜索。递归画廊在开启 Include subdirectories 时逐层加载所选目录。

前端职责边界：App 负责工作区和路由，阅读器负责文档翻页与阅读状态；播放器负责媒体交互；DocumentDetails 负责元信息格式和展示；文件、目录的系统打开动作通过 useSystemOpen 共用请求状态，API 模块负责具体接口。

所有文件共用渐进加载框架：路径与 DocumentToolbar 先显示，`/api/document/info` 只读取文件属性及最多 8 KiB 的类型头，与正文或编译请求并行执行。`useDocument` 提供正文并统一管理 Preview／Raw 视图，工具栏和阅读器使用同一个视图值；内容加载完成与阅读位置恢复进度分别传递。`useDocumentInfo` 按修改时间选择完整信息快照，同版本优先使用正文信息，不混合不同版本的字段；图片尺寸、EXIF 和视频探测通过独立接口异步补充。文档接口不调用媒体元信息服务；探测与缩略图／HEIF 转换使用独立的单线程任务队列，元信息任务不阻塞媒体转换。工具栏只接收所需信息，正文保持接口原样。DocumentReader 处理代码、Markdown、PDF、Typst 和 HTML；MediaReader 只管理图片的临时缩放和播放器，不读取或保存阅读位置，也不发送阅读进度。PreviewContext 提供渲染所需的文档与视口，Markdown 的准备结果和导航直接通过 props 传递。等待期间媒体复用缩略图，文档显示预览占位。

文档阅读位置、视图、缩放和 Markdown 折叠状态仅保存在当前浏览器：从内存同步读取，最多保留 100 个文件，变更按 500 ms 合并写入 localStorage；隐藏、离开页面或切换仓库时立即落盘，相同位置不重复写入。本地存储不可用时退回内存。阅读位置不再跨浏览器或设备同步，清除站点数据也会清除位置。后端仅在数据目录的 `file-history/` 中保存文件路径和访问时间，不再提供 `/api/reading` 接口。

局部布局使用 Tailwind；原生按钮、展开行、提示和空状态由 `web/ui.css` 统一，尺寸与颜色复用 `web/tailwind.css` 的主题变量。PDF 与 Typst 共用页面布局、加载状态和暗色适配；播放器 CSS 集中管理浮层外观及动态媒体几何。第三方组件的必要适配保留在独立规则中。

目录菜单的 `Browse as gallery` 可浏览图片及 MP4、M4V、WebM、OGV 视频。视频悬停时静音循环播放，也可开启画廊自动播放。播放采用总额 16 的分辨率预算：720p 及以下占 1、1080p 占 2、1440p 占 4、4K 占 8、更高分辨率占 16；竖屏按像素数同等计算，未知尺寸暂占 4，读取实际尺寸后调整。视口上下 120 px 内允许播放，离开后暂停并保留最多 8 个预览缓存；超出上下 800 px 持续 5 秒后卸载。切到后台保留视频节点与缓冲，返回后继续播放。实际播放能力取决于浏览器支持的编码与硬件加速，暂不转码。

照片、视频浏览页支持 `↑` / `<` 切换同文件夹上一个媒体，`↓` / `>` 切换下一个媒体，按文件列表顺序跳过非媒体文件，到首尾停止；输入框和滑块等控件保留自身的键盘操作。

超过 800 万像素或 8 MiB 的可解码图片由后端生成最长边 800 px 的缩略图（保留比例，不放大）。普通图片使用原图；超出当前解码器支持范围的格式仍交给浏览器。视频封面通过 PATH 中的 `ffmpeg` 抽帧，未安装时封面会显示失败提示，浏览器支持的视频仍可播放。

缩略图与 HEIF 完整预览按源文件路径、大小和修改时间缓存于 `LIBRARY_DATA_DIRECTORY/thumbnails/YYYY-Www/`（UTC ISO 周），重启后继续复用。只读取本周、上周两个目录，新文件写入本周，保留约 7～14 天。服务启动和跨周后在后台删除更早的周目录；不逐文件统计时间或总大小。本周命中直接复用；上周命中通过重命名移入本周目录，不复制文件，也不改写文件时间，从而按最近一次服务端访问续期约 7～14 天。浏览器直接命中自身缓存时不会触发服务端续期。跨周检测每小时执行一次，仅周变化时遍历顶层目录，过期文件可能延后最多一小时清理。旧平铺缓存不读取、不迁移、不自动删除，可手动清理。透明图片保存为 PNG，其他图片和视频封面保存为 JPEG。可删除该目录清理缓存，后续访问会重新生成。

媒体元信息与编解码使用独立的有界 worker 池：根据可用 CPU 数，元信息并行度为 2～8，缩略图及 HEIF 转换并行度为 2～4，每池最多排队 256 个任务。尺寸批量请求逐文件调度，慢文件不阻止空闲 worker 继续处理其他文件；返回顺序与请求一致。相同源文件版本、相同预览类型的并发请求共享一次生成，临时文件使用独立名称，成功后再发布缓存。FFmpeg 的解码、编码和滤镜线程数均限制为 1，避免每个转换任务再次扩张线程。

画廊每批仍展示 64 张卡片，元信息拆为每请求最多 16 项、最多 4 个并发请求；批次完成后按显示顺序统一提交，保持布局稳定。按拍摄时间排序时同样并发读取，但仍需取得全目录日期后才能确定全局顺序。切换目录或排序会取消旧请求；个别请求失败时仅缺失尺寸的卡片使用默认比例。

画廊自动播放有排队时，每 20 秒尝试轮换已开始播放的视频，避免高分辨率视频长期等不到预算。鼠标悬停 150 ms 或键盘聚焦可额外启动最多 1 个视频，不暂停其他视频来腾出预算；离开后重新纳入自动播放预算，必要时暂停并保留画面与缓冲。加载或缓冲超时为 60 秒，已缓冲数据增加会延长等待时间；排队与慢速加载分别处理。

媒体接口统一位于 `/{仓库}/api/media`：

| 请求 | 用途 |
| --- | --- |
| `GET /media?path=…&v=…` | 原始媒体，支持 Range 分段读取 |
| `GET /media/thumbnail?path=…&v=…` | 画廊缩略图和视频封面，无需缩放的图片重定向到原图地址 |
| `GET /media/preview?path=…&v=…` | HEIC/HEIF 的完整尺寸预览 |
| `GET /media/metadata?path=…` | 返回 `path`、`modified` 和带 `kind` / `details` 的媒体元数据，与画廊尺寸读取共用探测缓存 |
| `POST /media/open` | 请求服务所在机器用系统默认应用打开原始照片或视频 |
| `POST /media/dimensions` | 返回 `files` 数组，包含文件描述、已知尺寸和可选拍摄时间；接口最多接收 512 个路径，画廊每批请求 64 个 |

文件描述接口 `GET /document/info?path=…` 统一识别文件和目录，返回类型、MIME、媒体类别、浏览器播放策略和图片预览方式。前端将最近 100 个描述按仓库 API 路径和文件路径保存在 `localStorage`，每次访问仍向服务端校验；缓存未命中显示通用加载状态，不使用扩展名或文件树猜测阅读器类型。正文加载不等待文件树，媒体取得描述后直接加载资源与元数据，不再请求 `/document`。画廊批量返回的描述和尺寸写入同一缓存，因此从画廊首次打开媒体即可显示预览，并在后台校验；缩略图使用同一版本 URL 复用浏览器缓存，完整原图和视频仍按需加载。本地存储不可用时直接请求服务端。

文件描述中的 `preview` 字段只按格式选择：普通图片为 `original`，HEIC/HEIF 为 `converted`，不等待尺寸或 EXIF 探测。图片资源地址不随元信息到达而改变。媒体资源的 `v` 参数与源文件修改时间一致时启用浏览器私有缓存；无版本或版本不符时重新校验。画廊中无需缩放的图片重定向到详情页使用的原图地址，以复用浏览器缓存；大图缩略图与原图仍分别缓存。

HEIC/HEIF 使用 FFmpeg 转为 JPEG，分别缓存画廊缩略图和完整尺寸预览，原始文件保持不变。建议使用带 HEVC 解码支持的 FFmpeg 8.1 或更新版本，以正确处理 iPhone 常见的分块 HEIF。画廊将同目录、同名主干（忽略大小写）的 JPEG、HEIC 或 HEIF 与 MOV 合并为 Live Photo 卡片，使用照片封面并播放配对视频；暂不还原 HDR 增益图。

媒体处理按常用格式和正确扩展名设计；只有 `.ts` 额外检查文件头，以区别 TypeScript。详情页以浏览器实际加载的图片或视频尺寸为准，后端尺寸用于加载前占位；视频探测处理常见的 90°/270° 旋转。独立 SVG 的尺寸和显示完全交给浏览器，不做后端专门解析。PDF/Typst 的 SVG 页面直接使用各自解析/排版结果的尺寸，不经过此图片探测路径。画廊缺尺寸时接受 4:3 占位。元信息缺失不阻止预览，FFprobe 最多等待 10 秒，FFmpeg 缩略图或 HEIF 转换最多等待 30 秒，超时按读取失败处理。不自动重试、转码或修复异常文件，预览失败可用系统应用打开。动态图允许画廊大图缩略图为静态、较小原图保留动画；不增加动画重编码、特殊像素比例或额外 TS 变体兼容。磁盘缓存按周整批淘汰，不维护文件级 LRU 或容量统计。


## 构建与打包

```sh
npm run typecheck
npm run build
cargo build --release --locked
```

修改前端后重新构建，修改后端后重新编译并重启服务。

`npm run package` 在 `release/` 生成当前平台的部署目录和 `.tar.xz` 压缩包；打包环境需要支持 xz 的 `tar`（GNU tar 还需安装 `xz`）。GitHub 发布包也使用 `.tar.xz`，以减少字体下载体积。解压或复制整个目录后运行 `lib-ts`（Windows 为 `lib-ts.exe`），部署环境无需 Node.js。现有用户数据及 Typst 包缓存不随包复制。

现有回归检查：

```sh
node --test tests/*.test.mjs
cargo test --release --locked
```

独立 MPEG-TS（`.ts`）视频按文件内容识别，与 TypeScript 源码区分。画廊只显示抽帧封面，不进行悬停或自动播放。打开 TS 等不走浏览器播放的格式，或照片、视频预览失败时，可点击“Open in system application”，直接用系统默认应用打开原文件；不转封装、不生成视频副本，不支持 `.m3u8` 播放列表。系统打开与目录资源管理器共用隔离的平台启动接口；Windows 使用原生 ShellExecuteExW，标记用户发起操作并请求正常显示窗口，焦点切换仍受系统策略约束，不额外启动 PowerShell 或安装工具。其余平台沿用系统打开命令。该操作当前在运行 lib.ts 的机器上执行，需要桌面环境和对应的文件关联；前端通过 API 请求，不依赖本地绝对路径，未来可扩展其他打开目标。照片、视频工具栏默认显示文件大小和修改日期，像素尺寸及其他元信息在悬停或聚焦时显示。
